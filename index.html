nginx-web-node-plugin

A nginx proxy server configuration template for webNode.

Project status

Use case

This web-node plugin starts an nginx process as reverse proxy in front of your application server and stops it again when the application exits. Your application keeps a single entry point while nginx terminates TLS, serves static files or balances load.

Features included:

  • Starts and stops nginx together with your application.
  • Waits until the proxy URL is reachable before the application continues.
  • Optional mode: the application keeps running if nginx is not available.
  • Reload nginx at runtime, e.g. after its configuration changed.

Installation

nginx has to be installed on the system and available as "nginx" in the "PATH". Install the plugin next to web-node and the application server plugin it depends on. web-node discovers every installed package whose name ends with "-web-node-plugin" automatically:

yarn add web-node application-server-web-node-plugin nginx-web-node-plugin

Configuration

The plugin starts nginx without arguments, so nginx reads its default configuration file (usually "/etc/nginx/nginx.conf"). It has to contain "daemon off;", otherwise nginx detaches and the plugin can not track or stop it. The plugin settings live below "webNode.applicationServer.proxy" in your application's "package.json":

{
    "webNode": {
        "applicationServer": {
            "proxy": {
                "optional": false,
                "url": "https://127.0.0.1/"
            }
        }
    }
}
  • "url": Address nginx answers on. It is polled for up to three seconds after start and must answer with a status code below 400. Defaults to "http://127.0.0.1/".
  • "optional": If "true" (default) a failing nginx only logs a warning, otherwise the application stops.
  • "logFilePath.access" and "logFilePath.error": Log destinations, defaulting to standard output and standard error. They are meant to be used in a generated nginx configuration, see below.

Generating the nginx configuration

Combined with the EJS plugin you can derive the nginx configuration from the same web-node configuration. A template "nginx.conf.ejs" is rendered to "nginx.conf" before nginx starts. Link it to the location nginx reads, e.g. "/etc/nginx/nginx.conf":

<%_ const server = _.configuration.applicationServer _%>
daemon off;

events {}
http {
    access_log <%- server.proxy.logFilePath.access %>;
    error_log <%- server.proxy.logFilePath.error %>;

    server {
        listen 80;

        location / {
            proxy_pass http://<%- server.hostName %>:<%- server.port %>;
        }
    }
}

Services

  • "services.nginx": The running nginx child process or "null" if it is optional and could not be started.
  • "services.nginx.reload()": Runs "nginx -s reload".
  • "checkReachability(configuration.applicationServer)": Waits until the proxy URL answers, exported for use in other plugins.
